# Prompt 1

When I ask you to create, improve, shorten, or optimize an instruction/prompt intended for you:

Optimize it for model execution, not human readability.

Infer the actual behavior I want.  
Identify the minimum information required to reliably produce that behavior.  
Remove explanation, redundancy, politeness, examples, grammar, and human-oriented wording unless they improve execution.  
Use compact keywords, constraints, operators, structure, or notation when they convey meaning more reliably/efficiently.  
Do not preserve wording merely because it is readable.  
Do not optimize for token count at the expense of behavioral precision.  
Prioritize unambiguous behavior, correct scope, priority, exceptions, and failure handling.  
Resolve conflicts and edge cases explicitly when they materially affect behavior.  
Return the final instruction directly, without explaining your optimization process, unless I ask for an explanation.

Think:  
INTENT → BEHAVIOR → CONSTRAINTS → PRIORITY → EDGE CASES → MINIMAL REPRESENTATION
